Install ShieldLint

One Python package, no runtime dependencies, no network access at scan time. Three ways in: from source, through a container, or straight into CI.

From source

Until the package lands on PyPI, clone and install in editable mode.

git clone https://github.com/ace-coderr/ShieldLint
cd ShieldLint
python -m pip install -e .
shieldlint --version

Editable install puts shieldlint on your PATH and lets you edit the source without reinstalling. Use pipx install --editable . to keep it out of your project environment.

IsolatedDocker

Container

Mount the repository you want to scan and run the CLI against it.

docker build -t shieldlint .
docker run --rm -v "$PWD:/src" shieldlint \
  check /src --fail-on error

Nothing is written outside the mounted volume, and the container has no reason to reach the network.

Zero touchGitHub Actions

CI step

Fail the build on errors and upload findings to code scanning.

- uses: actions/checkout@v4
- uses: actions/setup-python@v5
  with: { python-version: "3.12" }
- run: pip install -e .
- run: shieldlint check . --format sarif -o s.sarif
- uses: github/codeql-action/upload-sarif@v3
  with: { sarif_file: s.sarif }
Localgit hooks

Pre-commit

Catch the leak before it reaches a branch.

# .pre-commit-config.yaml
repos:
  - repo: local
    hooks:
      - id: shieldlint
        name: shieldlint
        entry: shieldlint check --quiet
        language: system
        pass_filenames: false
Verify the install. shieldlint rules should print 14 rules, and shieldlint check examples/vulnerable-checkout should exit with code 1 and report 8 errors and 9 warnings. If both hold, the decoders and the lexer are working.

01 Before you ship

Roll it out without
drowning in findings.

A new linter on an old codebase produces noise. Sequence it.

01

Measure

Run shieldlint check . --quiet and look at per-rule counts. High counts in test fixtures are expected; high counts in payout code are the point.

02

Exclude what is not yours

Add vendored vectors and fixtures to exclude. Suppress deliberate fixtures inline rather than globally.

03

Ratchet

Start with --fail-on error, then promote warnings to errors once the baseline is clean. A ratchet that only ever tightens keeps the build honest.
