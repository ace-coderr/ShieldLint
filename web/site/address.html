01 What you are looking at

Anatomy of a Unified Address.

A Unified Address is a container. It holds one or more receivers, each with a typecode, so a wallet can pick the best one it supports — and a sender can silently pick the weakest.

How the encoding works

  1. Receivers are serialised as typecode ‖ length ‖ address, sorted by typecode.
  2. The human-readable prefix is padded to 16 zero bytes and appended.
  3. The whole payload is passed through F4Jumble, an unkeyed Feistel network.
  4. The result is encoded with Bech32m using the u or zu prefix.

Why the receiver set matters

ReceiverTypecodeEffect
Orchard0x03Shielded, strongest
Sapling0x02Shielded
P2PKH0x00Public — downgrade risk
P2SH0x01Public — downgrade risk

A u1… address carrying a transparent receiver is valid, but a sender that cannot do shielded will quietly use it. That is rule SL003.

Revision 2 (zu…) forbids transparent receivers outright. Revision 0 (u…) allows them. utest1… is testnet — shipping one to production is rule SL009.
