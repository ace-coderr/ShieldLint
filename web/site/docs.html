01 · Start here

Quickstart

ShieldLint needs Python 3.11 or newer and has no runtime dependencies. Install from source until it is published to PyPI.

git clone https://github.com/ace-coderr/ShieldLint
cd ShieldLint
python -m pip install -e .
shieldlint --version

Then point it at a tree. With no path it scans the current directory:

# the everyday command
shieldlint check src/

# one line for a CI log
shieldlint check src/ --quiet

# stricter: warnings fail the build too
shieldlint check . --fail-on warning
Exit codes are the CI contract. 0 means clean, 1 means findings at or above the threshold, 2 is a usage error. Wire the threshold once and every runner behaves the same.

02 · Start here

Reading a report

Text output is grouped by file. Every line carries the position of the literal, the rule id, the severity and the consequence.

$ shieldlint check examples/vulnerable-checkout

examples/vulnerable-checkout/checkout.py
19:19  warning  SL002  transparent address literal
32:6   error    SL006  Unified viewing key literal in source
65:16  error    SL011  invalid ZIP 321 payment request

8 errors, 9 warnings, 0 notes — exit 1
SeverityMeaningWhat to do
errorPrivacy is lost now, or the payment will not work.Fix before merging.
warningA weaker configuration that someone else can exploit.Fix, or explicitly accept it.
noteContext: testnet values, informational decoding.Usually nothing — verify intent.

The same data is available as JSON, SARIF or GitHub annotations with --format. The JSON shape is stable; SARIF is what code scanning needs.

03 · Reference

CLI reference

Five commands. check is the one that runs in CI; the others decode a single value or describe the tool.

CommandWhat it does
shieldlint check [paths…]Scan files or directories. Defaults to the current directory.
shieldlint rulesPrint the rule catalogue with severities.
shieldlint address <value>Decode an address or viewing key offline.
shieldlint uri <value>Parse and validate a ZIP 321 payment request.
shieldlint versionPrint the version.

--fail-on error|warning|note|nevererrorThreshold that turns findings into exit code 1.
--format text|json|sarif|githubtextOutput format. github emits workflow annotations.

--no-colorautoDisable ANSI colour.
--exclude GLOB—Skip paths. Repeatable.
--include-docsoffScan Markdown and documentation files too.

04 · Reference

Configuration

Drop a shieldlint.toml at the repository root. The CLI picks it up automatically; --config PATH overrides the search.

# shieldlint.toml
fail_on = "error"
include_docs = false
exclude = ["tests/vectors/**", "examples/vulnerable-*"]
disable = ["SL009"]

[shieldlint.severity]
SL002 = "note"
SL013 = "error"

severity overrides apply after the rule runs, so you can promote a warning to an error on a stricter codebase without forking the tool. disable removes a rule everywhere — prefer inline suppression when the exception is local.

05 · Reference

Suppressing findings

Two directives, both visible in review and both scoped. Vendored vectors and test fixtures are a legitimate exception; production payout code is not.

# silence one rule on one line
TEST_ADDRESS = "t1cN2ZVWzWcVRrnfeQzmkpLhzQ4dYRv8yRY"  # shieldlint: ignore[SL002]

# silence the whole file (fixtures, upstream vectors)
# shieldlint: disable-file
A typo cannot disable a check. An unknown rule id in a directive is itself a finding, so ignore[SL005] will never silently silence SL006.

06 · Reference

Zcash concepts you need

ShieldLint reports against four Zcash primitives. You do not need to implement them — just recognise what a finding is talking about.

Transparent vs shielded

A transparent address (like Bitcoin's) puts sender, recipient and amount on-chain forever. Shielded pools — Sapling and Orchard — encrypt the transfer. A Unified Address can contain several receivers, and if one is transparent, a wallet is allowed to use it.

Viewing keys and spending keys

A viewing key decrypts an account's incoming notes and memos without the ability to spend. It is still catastrophic in source or logs: it reveals every counterparty. Spending key material in a repository is worse.

Memos

A memo is exactly 512 bytes of arbitrary data encrypted to a shielded recipient. Invoices, order ids and customer identity routinely travel in it — which is why a memo on a transparent address, or an over-long literal, is a finding.

Payment URIs

A zcash: URI is the contract between a checkout and a wallet. ZIP 321 defines its grammar; a malformed request is a payment nobody can make. The validator shows every parameter and violation.

07 · Operations

CI integration

GitHub Actions

Fail the build on errors and upload the SARIF report so findings appear in the Security tab and on the pull request diff.

- uses: actions/checkout@v4
- uses: actions/setup-python@v5
  with: { python-version: "3.12" }
- run: pip install -e .
- run: shieldlint check . --format sarif -o shieldlint.sarif
- uses: github/codeql-action/upload-sarif@v3
  with: { sarif_file: shieldlint.sarif }

One-line composite action

The repository ships action.yml, so once it is public a single step is enough:

- uses: ace-coderr/ShieldLint@v0.1.0
  with:
    paths: src
    fail-on: warning

The repository's own pipeline runs the tests on Python 3.11, 3.12 and 3.13, uploads SARIF, and lints ShieldLint with itself. A rule that fires on the tool's own source fails the build.

08 · Operations

Docker & pre-commit

Container

docker build -t shieldlint .
docker run --rm -v "$PWD:/src" shieldlint \
  check /src --fail-on error

Nothing is written outside the mounted volume, and the container has no reason to reach the network.

pre-commit

# .pre-commit-config.yaml
repos:
  - repo: local
    hooks:
      - id: shieldlint
        name: shieldlint
        entry: shieldlint check --quiet
        language: system
        pass_filenames: false

09 · Under the hood

How it decides

The pipeline is deliberately boring: lex, decode, evidence, rules. Boring means deterministic, and deterministic means a finding is reproducible on your machine and in CI.

  1. Lex. A per-language scanner returns every string literal with its position, skipping comments and handling concatenation, raw strings, regex literals and interpolation.
  2. Decode. Each literal is tested against Bech32m, Base58Check, F4Jumble and the ZIP 321 grammar. Success produces a typed value; failure produces a reason.
  3. Evidence. A file-level model collects addresses, URIs, assigned names and payment call sites — this is what lets a rule follow a constant to the line where it is spent.
  4. Rules. Each rule is a pure function over the evidence. No rule performs I/O, so results are deterministic across machines.
Specifications, not regular expressions. A literal is reported only after it decodes. A string that merely looks like an address and fails its checksum is SL014, not SL001.

10 · Under the hood

Limitations

Knowing where a static analyser stops is part of trusting it.

  • No semantic analysis. ShieldLint follows constants inside a file, not across modules, and does not resolve values computed at runtime.
  • No on-chain inspection. It cannot tell you whether an address has been used, or what a transaction revealed.
  • Not a wallet. It never derives keys, signs, or talks to a node.
  • Language coverage is broad, not exhaustive. Unlisted languages are scanned line-by-line with the default lexer.
  • It cannot see configuration you do not commit. Values injected from the environment are out of reach by design.
